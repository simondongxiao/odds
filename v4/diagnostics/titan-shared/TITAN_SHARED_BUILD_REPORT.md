# V3 / V4 共享 Titan 数据层与 Fair Line Engine 验收

## 结论

已在现有 V3、V4 原地接入单一共享层；没有创建新预测版本。新链路为：

`Titan007公开快照 → Raw审计 → 标准化SQLite → AS-OF Feature Store → FFL/CMFL → 市场偏离 → V3/V4`

旧 V3/V4 历史冻结记录、方向、盘口、水位、概率和结算均未回写。

## 18项验收

1. **Titan 抓到哪些字段？** 比赛ID、列表日、赛事、主客队、北京时间、状态、比分、排名/阶段，亚洲盘开盘/即时/滚球线与双边水位，欧赔开盘/即时/滚球 1X2，大小球开盘/即时/滚球线与双边水位，显示公司、来源页、抓取时间和已有 XML fallback。
2. **哪些字段无法稳定获取？** 稳定 Titan 球队/赛事/赛季/球员原生ID、完整积分榜 W/D/L/GF/GA/积分、球员伤停、确认首发、轮换、旅行距离、两回合总比分、真实大众资金流、逐公司盘口路径与多公司广度。这些字段保存为 `NULL/MISSING`，不伪造。
3. **历史是否 AS-OF SAFE？** 是。查询强制 `available_at/result_available_at <= decision_at/training_cutoff`；同场快照不得跨时间分区；收盘线只作事后 benchmark。
4. **V3/V4 是否读取同一 Feature Store？** 是。调度器先生成唯一 `latest.json`，再通过同一个 `TITAN_FEATURE_STORE_PATH` 传给 V3、V4；共享层失败则阻断新决策。
5. **FFL 是否完全独立于当前亚洲盘？** 是。FFL 函数签名只有主队事实、客队事实、比赛上下文，不含 line/water；自动测试锁定这一点。
6. **CMFL 使用哪些市场？** 仅去水 1X2 与 O/U 总进球线，不读取亚洲盘或水位。
7. **Fair AH Curve 如何生成？** 先用 Poisson/Skellam 得到主队净胜球离散分布，再对 0、0.25、0.5…逐线映射 W/HW/P/HL/L；四分之一盘拆成相邻两线各半注，并由期望盈亏为零反推双边公平港赔。
8. **为什么不能只比较盘口档位？** 同一盘口在不同净胜球分布、水位和不确定性下有不同覆盖率与 EV；只看档位会遗漏价格，也会把比赛级信息压成机械方向。
9. **Market Quality 如何计算？** 当前基于快照时效、开盘/即时覆盖、欧亚大小球一致性、来源/公司广度和噪声。当前只有单一公开聚合/展示源，质量限制为 LOW，不能声称 Sharp 共识。
10. **Football Pull 如何计算？** 动态 Elo、主客场、近期 5/10 场攻防与积分、休息天数、联赛实力收缩、杯赛状态及可得阵容信息共同进入比赛级净胜球模型；缺失会扩大不确定性。
11. **Public Pull 是否只是 Proxy？** 是。没有真实同盘口资金流时明确为 `MISSING`，绝不把赔率变化冒充真实资金流。
12. **开深时如何区分四类原因？** 看跨市场与时间顺序：与独立 FFL/CMFL 同步且有事实更新偏 H1；向 CMFL 收敛且跨市场同步偏 H2；偏离 FFL 且缺跨市场支持偏 H3；单源、低覆盖、陈旧或不同步偏 H4。证据冲突则 MIXED/UNKNOWN。
13. **开浅时如何区分？** 使用相同四假设与证据链，不因“浅”本身判上盘；检查事实更新、CMFL 收敛/背离、公众叙事 Proxy、流动性和时间先后。
14. **是否允许 UNKNOWN？** **YES**。同时允许 `MIXED`。
15. **是否存在“开深=>下盘、开浅=>上盘”硬规则？** **NO**。盘口与 Intent 都只是解释/先验，不命令最终方向。
16. **是否已完成时间外校准？** 没有：`FAIR_LINE_UNCALIBRATED`。
17. **从哪天开始 FROZEN_FORWARD？** 2026-10-04；该日标记为基础设施启用日，第一笔记录必须来自启用后的有效赛前快照，不能用 10月3日旧赛果伪装 Forward。
18. **后续 V3/V4 是否强制先做 DB freshness check？** 是。正式入口先建共享库并检查 team/standings/schedule/odds 四类更新时间；失败或快照缺失时停止新决策与发布。
