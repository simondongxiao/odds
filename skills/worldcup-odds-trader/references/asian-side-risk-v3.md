## 1. 先分清这次修什么

旧程序以水位区间生成互斥标签，再查标签胜率选正反向。2026-09-04 的两场留底证明：同一档让球，只因水位跨过0.86或1.00，标签即改变，随后整组统计先验切换，推荐球队翻转。它没有证明机构真实意图被识别，也没有证明基本面发生变化。

v3要求四层：隐性基本面前置 -> 欧亚转换与意图交叉验证 -> 高热上盘/下盘结构与集中度审查 -> 历史EV、半盘结算、仓位及熔断。原标签/微观、同档否决、小样本反向警戒继续作为统计层；任何反向警戒均不能绕过新前置门。

新阈值都是待验证参数，不称为已证明有效的市场规律。`validation_status=shadow` 默认只做同规则纸面验证；没有按时间留出样本的校准结果，不生成可执行金额。不能为了修复两场输球事后选择最优参数。

## 2. 数据输入与时钟

每笔数据保存来源、事件时间、抓取时间、可用时间，最迟可用时间不能晚于决策时间。初盘是该机构第一次观测到的报价，永久保存；供应商后来回填的“初盘”单独存为修订值。9/4两场欧赔初赔在后一次抓取中也有改动，因此不能只比较字符串推断真实变盘。

| 类型 | 原始必需字段 | 校验 |
|---|---|---|
| 赛程 | match_id、list_date、league_id、国家、联赛/杯赛/级别、home/away、kickoff_utc、kickoff_bj、阶段/回合、累计比分 | list_date冻结；延期不重分日期；90分钟与晋级分开 |
| 欧赔 | bookmaker_id、market_id、初/即主平客decimal赔率、报价时间、抓取时间、pre/live | 逐机构去水后取稳健共识；不能把跨机构“最高赔率拼盘”当单机构 |
| 亚盘 | bookmaker_id、初/即让球、双方HK水、market_status、盘口时间、报价可执行性 | 统一为所选球队的有符号让球，给让为负；球探正值主让须转换；平手单列 |
| 大小球 | 初/即时真实总进球线、O/U水、机构与时间 | 深盘转换需要净胜球分布约束；不能默认2.5 |
| 基本面 | 最近及下一场开球时间、7/14天场数、旅途/客场、核心缺席与替代者、阵容深度、轮换风险、近5场及主客拆分、战意/杯赛状态 | unknown不等于没有伤停/无需轮换；H2H仅作旁证 |
| 情绪/资金 | 市场与结算口径、真实成交/注单/资金比例、窗口起止、流动性、来源 | 赔率变化不是投注量；累计成交不是单边资金 |

首发约T-60分钟重新核对；此前标预计。密集赛程（如休息<=72小时、7天>=3场）只是审查触发器，须同时评估替补深度、人员使用和下一场优先级。证据源沿用球探/官方俱乐部与联赛/SofaScore/FotMob等现有梯队，不能把网页可访问当字段已抓全。

采集窗口沿用既有列表日分段；建议T-24h/T-6h/T-60m/T-30m额外留底。报价新鲜度上限初始设为10分钟、跨市场最大时间差120秒，均应按数据源实际刷新频率校准。若没有源报价时间，不宣称秒级实时。

`Fundamental_Status`: pass / reduced / pending / veto。必须先审查双方的赛程、核心伤停、轮换/深度、战意四项。高风险且缺乏替代能力为veto；缺任一项为pending；可解释、可量化折扣的风险为reduced。状态为pending/veto时，可显示价格原始候选，不能显示已通过的真实意图或可执行投注。

## 3. Delta_Conv的唯一口径

仅靠欧赔胜平负无法唯一推出-1.25等深盘的公平水位。必须先取得与本场同一时点的净胜球分布：基于历史比分/攻防的已校准模型（如Poisson/Dixon-Coles），用欧赔去水和真实大小球共同约束。保存模型版本、训练截止时间、拟合残差、不确定区间；不得使用当前待检验亚盘本身反推分布后再声称完成独立交叉验证。

对于选中球队、实际让球h，将四分之一盘拆为相邻两档，各半注。以比分分布计算全赢P_W、赢半P_HW、走水P_P、输半P_HL、全输P_L。

```
A = P_W + 0.5 * P_HW
B = P_L + 0.5 * P_HL
Theo_Water = B / A                     # 公平HK水
P_Euro_AH = A / (A + B)                # 结算权重胜率，不是赢球概率
P_AH = [1/(1+w_side)] / [1/(1+w_side) + 1/(1+w_other)]
Delta_Conv = P_AH - P_Euro_AH          # 概率差；0.03=3个百分点
Delta_Water = w_side - Theo_Water
EV_current = A*w_side - B - costs
```

两边分别计算，明确Side=upper/lower/team；禁止把主客位置当上下盘。Delta为负说明该侧亚盘隐含概率低于欧赔模型转换值；为正则相反。它描述价格偏离，不直接描述资金流或庄家动机。

历史门槛也使用同口径：A_count=红+0.5红半，B_count=黑+0.5黑半，p_eff=A_count/(A_count+B_count)。旧“有盈利的场次/非走场次”继续显示为旧命中率，但不能直接当p_eff。当前价格的历史EV重估为(w*A_count-B_count)/全部有效已结算场次（走水净收益0），再减成本。

保留用户规定的方向平滑：`p_comb=(n*p_local + M*p_global)/(n+M)`，且正反方向各算一次。注明全局含局部，权重有重叠，该式是既定加权规则，不是独立样本的严格贝叶斯后验；不能把n+M当有效独立样本数或扩大置信度。所有样本必须在decision_at之前已知结算。

### 意图与偏离度映射

以下阈值仅为初始影子验证区间，须按联赛/深度/距开赛时间做留出验证后才可启用：

| 原始候选 | 独立校验 | 新结论 |
|---|---|---|
| 阻上/诱下 | 上盘Delta在-8至-3pp，基本面支持穿盘，阻力成立，无可核实上盘过热未阻住，至少两个机构的同步报价方向一致；不强制等待第二次更新 | 阻上验证候选；只有EV/风控全过才允许上盘 |
| 诱上/阻下 | 上盘Delta>=+3pp，基本面不足支持让球深度，公众热度及低门槛有独立证据 | 诱上警报、上盘否决；重新评估下盘自身EV |
| 降温保护/诱下 | 退盘但阵容/攻防与净胜球尾部仍支持上盘，转换价值没有消失 | 可考虑真实降温；不等同诱上，也不自动否决 |
| 任一标签 | 基本面、欧亚偏离方向互相矛盾；只有单一水位跨档而无独立证据 | 意图冲突/待核；证据完整时允许单次更新立即反转 |
| 任一标签 | abs(Delta)>10pp或拟合残差大/报价不同步 | 数据/模型异常检查，不升为高置信度 |

示例（假设数据，不是真实比赛）：Theo_Water=0.85、上盘水0.96、下盘水0.92，则P_Euro_AH=54.05%，P_AH=49.48%，Delta=-4.57pp。满足负偏离区间仍只说明可能有上盘价格价值；必须同时有基本面支持、实际阻力和最终收益优势。禁止写成“Delta=-4.57pp，所以庄家一定阻上”。

恢复原水位敏感度：一次新报价跨0.86或1.00可立即更新原始标签候选并启动完整重算，不要求两次新快照或5分钟间隔。必须保留前一基准快照以比较变动，排除换源/换机构/换模型造成的假变盘。改成另一球队前执行[被动调价与逆公众阻力检查](market-move-weekend.md)：被动追热不跟随；证据待核不强行改向；独立阻力支持新侧且其全链条通过，允许完全反转。任何新侧都重新查截至当时的历史与当前真实盘口，不混搭旧先验。新伤停或价格失效可立即暂停当前执行，不必等反向条件满足。

## 4. 高热上盘与下盘结构

高热必须有证据：可核实真实资金占比超过同市场理论基准5pp，或多源公众一致看强的定性记录（只能标定性热，不能伪造比例）。欧赔ML胜率与亚盘穿盘概率代表不同事件，不能简单平均后叫真实理论资金占比；跨市场资金比较仅作代理，不能单独触发硬否决。

高热 + 下列任一已证实风险，否决上盘执行：阻力不足且仍给超额甜水；诱上证据通过转换和基本面双检；双线赛程/客场体能与薄阵容叠加；重要攻击点/中卫/门将缺席而穿盘估计未覆盖替代损失。仅有深盘、名气或“降温保护”文字不触发。

下盘主动审查必须包括：近5场主客拆分失球/xGA（无xGA可用实际失球并注明）、对手强弱、主场防守和低位/反击路径、守门员/中卫可用性、丢球后是否被迫压上、受让档位的一球/两球缓冲。同盘口持续下盘降水可作价格保护证据，必须排除换机构、升降盘和报价不同步。

不存在单凭“防守好”或“深盘”自动买下盘的规则。下盘仍须通过自己的当前水位、精确结算EV、同档否决及风控。

### 上下盘暴露

分母为去重、冻结的有效有让球决策；平手盘单独列出，不硬归上盘。分别报告笔数比例与金额比例；观察候选、可投计划和真实成交分开。全局、微观板块、国家、联赛/杯赛及周末/工作日分别统计。

80%是结构审查线，不是预测胜率线。当前批次>=8场且上盘>80%触发批次预警；近30笔有让球决策覆盖至少3个列表日，笔数或金额上盘占比严格超过80%时，触发长期集中度风控。4/4仅显示小样本偏重，不能宣称长期偏差已证实。

触发后加强下盘信息收集和上盘反证审查（不是提高下盘准入门槛）：上盘安全垫由2pp临时提高至4pp、上盘仓位上限减半；合格下盘维持同一收益门槛，不为配平而降标准。新批次用上一日冻结暴露触发，批内先统一打分再整体确定集中度及仓位，避免列表遍历顺序改变结果。两边投注不同比赛并不保证风险对冲，不能以“对冲”名义增加总资金暴露。

## 5. 仓位、冷却与周末审计

仓位使用p_size=min(历史综合/一致方向胜率, 独立模型结算权重胜率, 已验证概率下界若有)。保留走水及各侧半赢/全赢条件结构，重加权五状态概率后，再用收益r={w,w/2,0,-0.5,-1}求最大化sum(P*log(1+f*r))的广义Kelly，取1/4 Kelly。重加权只用于保守EV和仓位，不回写Delta模型。不能把四分之一盘口当普通二元盈亏。

```
planned = Bankroll * unit_rate * signal_multiplier * blind_multiplier * day_multiplier * upper_multiplier * fundamental_multiplier
stake = min(planned, Bankroll*0.25*Kelly_f, Bankroll*single_match_cap, remaining_daily_capacity)
```

unit_rate沿用现有配置（当前标准5%），single_match_cap默认5%。普通通过signal=1；高置信度、转换持续一致且样本外通过可用1.5，但不得突破单场及Kelly上限。只因Delta更大不加仓。绝对让球0.75-1.0在缺乏独立分层验证时blind=0（只观察）；完成该档留出验证后仍先blind=0.25。该档不被永久认定亏损，须有分层证据才能解除。日预警day=0.5，静默day=0；基本面reduced时fundamental=0.5，否则pass为1。金额向下取整；不足最低20元时不执行，绝不为满足最低额向上凑仓。

每个联赛、盘口档位、微观板块分别跟踪已知结算。按日批量更新次日仓位；同日并发单不使用未来或尚未结束的比赛。保留既定日风控：上一完整有赛日ROI为负，次日至少半仓；降级保持至满足下面的恢复条件。真实改价/紧急伤停可以停执行，但不改原计划记录。

“Delta预期相反”须在赛前冻结expected_cover_side及理由。赛后该侧净收益<0记反例，全黑=1、黑半=0.5，走水不增不清，正收益清连败。连续反例达到3个全黑等价 -> 次日半仓；达到5个或该系列连续两个结算日负ROI -> 次个有赛日静默。统计必须固定版本、唯一比赛、同口径盘口；不能用后来最有利的版本。

静默期间仍保存影子计划及结算以检验恢复。至少一个完整有赛日、>=3场影子已结算且ROI>0时，次日恢复（恢复条件是待验证的操作参数）；缺样本继续冷却，无比赛的日历日不当作亏损日。每次状态变化记录触发比赛ID、旧/新状态、证据截止日。

周末下滑首先做归因：周末/工作日 × 联赛/杯赛 × 上下盘 × 档位 × 水位 × T-24h/T-6h/T-1h × 版本，分别统计红/红半/走/黑半/黑、结算权重胜率、真实水位ROI、样本和区间。先核查混入赛后快照、当日历史污染、抓取来源变化、杯赛轮换和深盘占比。未完成同条件比较前，不写“周末必输”或“晚版必胜”。

2026-09-08最新指令取消周末统一加严10%-15%。所有日期恢复 `Threshold = 1/(1+Water)+Safety_Buffer`，不因周末调整仓位、否决上盘或强制转下。周末仅保留统计分类；已有基本面、杯赛、同档、集中度和冷却规则仍按各自证据执行，不受此次取消影响。

## 6. HTML、飞书与执行工作流

Python为唯一决策入口，HTML只渲染保存的decision，不在浏览器按当天总历史重新选队。采用版本化Decision/Snapshot + 单独Settlement表。

追加稳定字段（不删除旧列）：

| 字段 | HTML中文名/含义 |
|---|---|
| rule_version / decision_id / snapshot_id / history_cutoff | 规则版本/计划版本/盘口版本/历史截止 |
| Fundamental_Status / Fundamental_Failed_Gates | 基本面校验/具体缺口 |
| Raw_Intent / Verified_Intent / Intent_Stability | 价格候选/交叉验证意图/持续性 |
| Theo_Water / Actual_Water / P_Euro_AH / P_AH | 理论水/即时水/转换权重胜率/亚盘隐含 |
| Delta_Conv / Delta_Water / Conv_Status | 欧亚偏离(pp)/水位差/转换校验状态 |
| Model_Version / Model_Cutoff / Validation_Status | 分布模型版本/训练截止/影子或已校准 |
| Upper_Heat_Status / Upper_Veto / Dog_Evidence | 上盘热度/否决理由/下盘结构证据 |
| Upper_Count_Share / Upper_Stake_Share / Exposure_Status | 上盘笔数及金额占比/集中度状态 |
| Effective_Rate / EV_Current / Safety_Buffer | 结算权重胜率/当前价净EV/安全垫 |
| Blind_Multiplier / Risk_State / Stake / Execution_Status | 盲区仓位系数/冷却状态/金额/执行状态 |

红框保持紧凑：原标签总体表现 + 当场所选球队/方向 + 可执行/不执行及首个失败门。增加“基本面/欧亚校验”折叠详情列出上述字段。不在红框堆公式。

Execution_Status枚举：OBSERVE（观察）、DATA_PENDING（数据待核）、VETO_UPPER（否决上盘）、CONV_CONFLICT（转换冲突）、COOLDOWN（冷却）、BELOW_MIN_STAKE（不足最低额）、READY（计划可执行）、EXPIRED（报价过期）、FILLED（有真实成交回执）。赛前是否可投与现在是否可执行分别保存；已开赛不可新执行，不得因此改赛前可投结论。

飞书建议四表：比赛名册（match_id/list_date），盘口快照（snapshot_id），决策版本（decision_id，关联合同与快照），赛果/执行回执（decision_id+settlement_version）。若另设RiskState表，按region/league/line+effective_date作键。只更新相应record_id，重试先按本地outbox事件ID去重；禁止整表清空再上传。客户端幂等记录不依赖未核实的服务端参数。

工作流：

1. 抓取并原样落盘 -> 匹配名册 -> 同步时间/盘口方向/机构校验 -> 追加快照。
2. 读取决策时已可用基本面 -> 形成独立净胜球分布 -> Delta/意图双检 -> 标签与微观顺序历史 -> 精确EV -> 暴露/盲区/冷却 -> 固化decision。
3. 先落本地decision和outbox，再同步飞书记录、HTML与GitHub；失败保留原页面和重试事件，不清空历史。HTML和飞书的决策字段必须有相同decision_hash。
4. 人工执行清单或已授权执行器再次验证开赛状态、盘口线、可成交水位、金额和过期时间，得到成交回执才能写FILLED。报价变化重新计算新增版本。此模块不自动下注。
5. 比分仅更新Settlement；复盘按原成交/计划线水结算。每个版本独立比较且明确其是否赛前，不挑选赛后赢家版本。
